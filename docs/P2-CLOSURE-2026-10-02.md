# Закрытие P2 — TestoCMS, 2 октября 2026

## Область и состояние приёмки

Реализованы все **25 P2: 7 DEP, 10 ADM, 8 PUB** из [исторического аудита](CMS-AUDIT-2026-09-30.md). Исправления выполнялись тремя прежними агентами; общий агент интегрировал DB mutex, порядок блокировок, обновление пространства кешей и межпроцессные проверки. Статус «закрыт» относится к указанному дефекту и воспроизведённым ниже серверным/HTTP-сценариям. Дополнительные непроверенные GUI и внешние сценарии перечислены отдельно и не объявляются прошедшими.

Ни production-развёртывания, ни платных обращений к LLM не выполнялось. Все разрушительные операции проводились в `/private/tmp/testocms-p2-*`, отдельных Docker volumes и базах `testocms_p2_*` / `testocms_p1_restore`. Пользовательские `.env`, БД, storage и файл `testocms` не использовались как тестовые данные.

## Принятые контракты

- Авторское содержимое public и stage совпадает: первый H1 сохраняется, автоматические hero/заголовок/служебные плашки удалены. Настроенные тема, шапка, подвал и SEO остаются; опубликованный `home` — прежний контракт главной.
- Языковой переключатель ведёт только к существующим доступным переводам. Фильтр locale применяется до paginate/limit; поиск сохраняет `q/type`, переключение сбрасывает страницу.
- Используемые медиа удалить нельзя. API возвращает 409 `asset_in_use` со списком использований; ошибка до завершения удаления — 503 `asset_storage_cleanup_failed`; успешное удаление — 204. Принудительного удаления нет.
- Категории: PATCH сохраняет пропущенные поля/локали, `null` очищает nullable-поля, `false` отключает категорию; `remove_translations` удаляет явно. PUT заменяет набор переводов. Это несовместимо с прежней upsert-семантикой PUT.
- `cms:setup --redo` изменяет текущий экземпляр с сохранением DB identity, web root и APP_KEY. Миграции/demo seeding в redo не запускаются; прерванная операция требует `cms:setup:recover {operation}`.

## Общая интеграция и миграции

1. `2026_10_02_000100_create_content_mutation_guards`: singleton media/category mutex. Порядок media guard → category guard → сущности; SQLite заранее получает writer lock через no-op UPDATE. Registration, delete, page/post/category/template/chrome/theme mutations используют один mutex. Поздняя запись ссылки после удаления получает422.
2. `2026_10_02_000200_add_authored_search_projections`: backfill пачками по100 без изменения авторского HTML/blocks/timestamps; DB-specific индексы. Клиент не управляет search_text.
3. `2026_10_02_000300_create_cms_installation_table`: nonsecret installation UUID/runtime identity защищает от случайной инициализации неожиданной БД при существующем marker. Legacy adoption требует явного `--adopt-existing --force`.
4. Единый `PublicContentVersionService::CACHE_SCHEMA = public-v3` разделяет HTML, slug и SEO cache keys от прежней версии. Regression с отравленными P1 ключами подтверждает, что старые demo HTML/slug/sitemap не выдаются.
5. Исправлен rollback P1 schedule migration: индекс cancelled_at удаляется до колонок в SQLite. `PublicationScheduleMigrationTest` выполняет up/down/up и проверяет данные/уникальность pending.
6. Повтор P1 обнаружил, что назначение publish ещё меняло draft в scheduled. Исправлено: назначение/перенос не меняют текущий статус; сохранение body у draft сохраняет ожидающее расписание, отдельное manual unpublish отменяет его. Обновлены регрессии правильного поведения.

## Ограничения и поставка

- GitHub CI изменён для PHP8.2–8.5, MySQL/PG content+races, file/Redis drivers; удалённый CI не запускался и не объявляется прошедшим. Локальный фактический прогон отражается отдельно.
- Внешний storage проверяется mock-адаптером (false/exception/retry/rollback), не реальными S3 credentials. Удалённый storage и DB не являются одной атомарной транзакцией. Private backup/purge recovery отражён в журнале; при ошибке purge после commit возвращается503 с описанием уже выполненного удаления, а не обещанием сохранённой записи.
- Local disk удаляет только assets/*; приватные setup/update journals нельзя удалить, зарегистрировав их как media. Старые private attachments вне этого пространства требуют контролируемого переноса оператором.
- Chrome bridge завис на native file chooser и затем стал недоступен. Выбор файла, оставшиеся удаления и мастер через GUI не приняты: HTTP-проверки этих серверных сценариев перечислены отдельно, они не подменяются заявлением об успешных GUI-кликах.
- Для атомарного local quarantine public disk и приватный storage должны находиться на одном filesystem; нестандартный separate filesystem возвращает503 без удаления записи. Штатные оба Compose используют общий storage volume.
- Все LLM payload — fixtures/fakes. Live paid provider calls исключены согласованным планом.
- Поставка пользователю/production не выполнялась. Миграции и несовместимый category PUT описаны в [API инструкции](admin-content-api.md), OpenAPI и deployment docs.
- Официальный подписанный release ZIP/реальный внешний release pipeline для **DEP-03 P1** остаётся отдельным незавершённым пунктом [P1 отчёта](P1-CLOSURE-2026-10-01.md). Закрытие P2 не подменяет его проверку.
