## VPS

Отдельный project `testocms-p1-vps`, PostgreSQL 16.14, nginx, localhost-порт 18973, новая сеть `10.253.237.0/24`, новые volumes, `.env` read-only. В контейнеры смонтированы полные текущие исходники и полный независимый `vendor/`. Основной smoke проходит в production окружении.

Зафиксированы успешная первоначальная установка и init gating, затем повторный `up`: init завершился с кодом 0 до запуска app/queue/scheduler; HTTP `/up` и `/healthz` — 200, форма входа — 200, CSRF/login — 302, авторизованная страница страниц — 200. Медиа GET/HEAD — 200, Range — 206; новый файл виден сразу, удалённый — 404. Символическая ссылка отсутствует. `.env` hash, количество администраторов и fingerprint пароля совпадают между запусками. Literal `$` в пароле сохранился; shell-выражение из dotenv не исполнялось.

После исправления общего runtime пользователя app/queue/scheduler оставались running с `RestartCount=0` через несколько циклов scheduler. `pg_dump` — 16.15, сервер — 16.14. Реальный payload smoke сохраняется в `docs/p1-verification/deployment-vps-*.json`.

При старом PHP image первоначальная попытка выявила перенос `storage/installed` через volume copy-up: init ошибочно считался завершённым при пустой PG базе. `.dockerignore` теперь исключает runtime storage, legacy public storage и сгенерированные bootstrap caches; Dockerfile создаёт writable каталоги до Composer. В smoke `nocopy` обеспечивает пустые volumes при повторном использовании старого runtime image.

Вторая попытка выявила root-owned lock/log при CLI root и FPM www-data. `docker/artisan.php`, `docker/prepare-media.php` и завершаемые PHP CLI команды используют общий uid/gid www-data. Dotenv разбирается библиотекой без shell execution. FPM master продолжает штатный запуск от root. Root отдельно исправил права shared update gate и перенёс регистрацию модулей в booted, чтобы Eloquent resolver был готов.

## Сборка и границы проверки

Полная первоначальная production Docker build с `--no-dev` успешно завершилась, включая компиляцию PHP extensions и Composer package discovery без `.env`/БД. Тег `testocms-app:p1-vps-smoke` относится к snapshot до финальных runtime helpers и pin16.

Последующий latest-source image `testocms-app:p1-vps-source` успешно собран поверх этого production runtime с PG16 tools и повторным Composer `--no-dev`; внутри image нет `.env` и `storage/installed`, есть vendor и новые helpers. Проверка использует текущий исходный код через read-only bind mount; изменение CSP и поздний browser fix форм также синхронизированы в эту копию.

Финальный canonical `Dockerfile` с `postgresql16-dev/client` не компилировался повторно с нуля после изменения pin16. Наличие обоих пакетов 16.15 в репозитории нового Alpine подтверждено. Его полная сборка остаётся release/CI проверкой; это не выдаётся за проверенный неизменённый финальный image.

## Дополнительный критерий перезаписи

Smoke расширен для overwrite существующего canonical path: повторная запись другого содержимого и другой длины, немедленный GET новых байтов, HEAD новой длины, изменение ETag и условный GET с прежним `If-None-Match`, который должен вернуть 200 с новым содержимым. Apache выполняет ту же проверку при оставшейся неизменной старой физической копии. Re-runnable проверки: `docker/smoke/vps-check.php` и `docker/smoke/apache-rewrite-check.php`; последняя защищена проверкой искусственного media-only marker, чтобы не изменять реальную установку.

Обе проверки реально выполнены успешно: содержимое заменено на 19 байтов, GET — 200 с новым телом, HEAD — длина 19, ETag изменился, запрос со старым ETag — 200 с новым телом. Доказательства сохранены в `deployment-vps-overwrite.json` и `deployment-apache-smoke.json`.

После завершения browser и HTTP проверок оба изолированных стека остановлены: VPS удалён через `compose down -v`, Apache контейнер и два его volumes удалены по точным именам. Повторные списки контейнеров и VPS volumes пусты. Рабочие Docker projects и volumes не удалялись. `pint --test` для всех Docker PHP helpers/smoke и `git diff --check` прошли.
